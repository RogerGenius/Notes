# 目录结构与分类说明

顶层分类的「坐标系」是**知识领域**，不是技术栈清单。技术会过时，领域长期稳定。

## 一、各顶层目录用途

| 目录 | 用途 | 归属关键词 |
|------|------|-----------|
| 00_Inbox | 收集箱，暂时无法归类的笔记 | 待定 |
| 01_知识库规范 | 库规、标签体系、分类说明（本目录） | 规范 |
| 10_计算机基础 | 跨方向通用的语言与理论 | Java/C/Python、数据结构算法、网络、架构方法论、Git |
| 15_Web开发 | 浏览器端 + 服务端业务开发 | Vue、React、Spring、Node、鉴权、接口 |
| 20_数据库 | 数据库的一切，含安装部署 | MySQL、Redis、MongoDB、Elasticsearch |
| 25_服务端基础设施与中间件 | 承载应用的运行时设施 | Nginx、Nacos、Docker、K8s、消息队列、CI/CD、监控 |
| 30_移动开发 | 产出物是移动 App 的技术 | Android、Flutter、小程序 |

## 二、三条核心划分规则

1. **每个知识点只有一个「家」**：按主体用途归一处，交叉关系用 `[[链接]]` 和标签打通，**绝不重复建目录**。
2. **按「运行环境 / 产出物」划分前后端与移动**：浏览器端 → 前端；服务器端 → 后端；产出移动 App → 移动开发。
3. **「使用/实操」与「原理/研读」分层**：操作系统原理在 10（理论），Linux/Windows 操作在 40（实务）；用 Spring 在 15，读 Spring 源码在 45。

## 三、常见归属判例

| 场景 | 归哪里 | 依据 |
|------|--------|------|
| Nginx、Nacos | 25 基础设施 | 主体身份是「运行时设施」，非业务代码 |
| Spring Cloud + Nacos 组合 | Spring 在 15，Nacos 在 25，笔记互相链接 | 各归各的家 |
| React Native | 30 移动开发，非前端 | 按产出物划分 |
| Node.js 后端 | 15 后端，非前端 | 按运行环境划分 |
| MySQL 的安装部署 | 20 数据库 | 部署动作不搬家，跟随主体知识 |
| Linux 命令 vs 服务器部署 Nginx | 命令在 40，部署在 25 | 40 管系统怎么用，25 管应用怎么跑 |
| C 语言（写 STM32 用） | 10 编程语言 | 语言本体是通用根基，嵌入式特有写法放 35 |
| 未来出现全新方向 | 先进 00_Inbox，攒多后再申请新顶层号 | 顶层留有大段空号可插类 |

## 四、如何新增笔记

- 已确定归属 → 直接在对应顶层目录下按需新建二级目录和笔记。
- 不确定归属 → 先放 [[00_Inbox/_说明|收集箱]]，整理时归类。
- 二级目录按需创建，规则同顶层：两位编号、留少量空隙、命名清晰。

## 五、如何新增顶层领域

1. 确认现有 12 个领域都不合适。
2. 从空号中挑一个合适的两位数（如 12、60、65…），命名 `编号_名称`。
3. 在本文件「各顶层目录用途」表补一行。
4. 更新 [[README]] 的目录速览表。
