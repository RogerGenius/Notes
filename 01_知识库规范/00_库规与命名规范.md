# 库规与命名规范

本知识库的统一规则。所有笔记（含 AI 辅助整理）都应遵守。

## 一、目录编号规则

- **所有目录名以「两位数字 + 下划线 + 名称」命名**，例如 `15_Web开发`。
- 编号**固定两位（00–99）**，永不使用三位数——这是为了在 Obsidian 文件树（按字典序排列）中保持排序正确。
- 顶层目录**按跨度 5 留空位**（00、01、10、15、20、…），两个相邻领域之间预留 4 个空号，方便日后插入新领域而**无需重命名既有目录**。
- 二级及以下目录**在各自父目录内独立编号**（01–99），同样固定两位、留少量空隙。
- **不要随便改目录名**：改名会牵动笔记里的 `[[链接]]`。

## 二、文件命名规则

- 文件名使用**简短、明确的中文或英文**，避免无意义的 `1`、`新建文档`、`abc`。
- 同一目录下用 `序号_名称.md` 保持顺序（序号两位，如 `01_xxx.md`）。
- 专题越分越细时，先问自己：**这个内容值得独立成一个文件吗？** 相关度高就合并进一个文件，可独立成章时才拆分。
- 文件名中避免出现 `/ \ : * ? " < > |` 等特殊字符。

## 三、frontmatter 规范

每个笔记文件开头用统一的 YAML 头，键名固定如下（值用中文）：

```yaml
---
type: 知识点        # 知识点 / 踩坑 / 教程 / 备忘 / 收集
status: 待整理      # 待整理 / 已整理 / 归档
tags:
  - 类型/知识点
  - 生态/xxx        # 按实际所属生态，可多个
created: 2026-10-20
updated: 2026-10-20
source:            # 可选：来源链接 / 书名 / 视频名
---
```

- `tags` 键名**必须用英文**（Obsidian 只识别英文 `tags` 作为标签系统）；取值统一用「分类/值」的嵌套形式，见 [[01_知识库规范/02_标签体系]]。
- `updated` 在每次修改后同步更新。

## 四、内链（双向链接）规范

- 提到其他笔记中的概念时，用 `[[笔记名]]` 建立链接，而不是重复写一遍。
- 链接目标是「知识」，不是「装饰」：只在确有参考关系时加链接。
- 交叉领域的笔记，用 `[[链接]]` 打通「主要归属地」与「其他相关方向」，配合标签做多向检索，**不要重复建目录**。

## 五、维护原则

- **人定规则、AI 做执行**：目录/标签体系的顶层设计由人拍板；AI 负责批量格式化、补标签、生成索引、整理 Inbox 等机械操作。
- 任何结构性改动（建目录、移动笔记、改分类体系）应「AI 提议、人确认」后再执行。
- 笔记**先落 Inbox，再定期整理归类**，避免因「不知道放哪」而乱弃。
