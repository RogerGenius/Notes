# 标签体系

目录决定笔记的「家在哪」，标签解决「还能从哪些角度找到它」。标签与目录互补，不重复。

## 一、标签命名规则

- 统一使用**嵌套标签**：`大类/小类`，例如 `类型/踩坑`、`生态/Java`。
- 一个笔记可打多个标签。
- 标签用简体中文（生态名等专有名词除外）。
- 新标签按「已存在的分类下补值」为主，不轻易新增「大类」。

## 二、三大常用标签族

### 1. 类型（这条笔记是什么）

`#类型/知识点`、`#类型/踩坑`、`#类型/教程`、`#类型/备忘`、`#类型/对比`

### 2. 状态（这条笔记整理到哪一步）

`#状态/待整理`、`#状态/已整理`、`#状态/归档`

### 3. 生态（属于哪个技术生态，用于跨目录检索）

`#生态/前端`、`#生态/Java`、`#生态/数据库`、`#生态/基础设施`、`#生态/移动`、`#生态/嵌入式`、`#生态/Linux`、`#生态/Windows`、`#生态/云服务`、`#生态/大疆MSDK`、`#生态/考公`……

> 生态标签的作用：比如 Nacos 笔记在「25 基础设施」目录，但打上 `#生态/Java` 后，从 Java 视角也能检索到它——这就是「交叉知识靠标签打通，不靠重复建目录」。

## 三、使用示例

一篇「Nacos 作为 Spring Cloud 注册中心的踩坑记录」：

```yaml
---
type: 踩坑
status: 已整理
tags:
  - 类型/踩坑
  - 生态/Java
  - 生态/基础设施
created: 2026-10-20
updated: 2026-10-20
---
```

## 四、维护约定

- 打标签宁少勿滥：通常 2–4 个足够，全打一遍等于没打。
- 生态标签随实际使用**逐步新增**，新增后在此文「生态」一行补登记，保持体系可查。
